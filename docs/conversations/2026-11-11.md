### MCP 怎么改

1. **让 Registry 条目直接生成接入表单。** 后端读取 `remotes` 里的端点、变量和请求头。公开服务可以直接检测，需要 API Key 的就显示对应输入框，需要 OAuth 的就引导用户到服务商授权。GitHub 继续保留仓库级限制，作为通用接入上的一条专用权限规则。 [Registry 条目格式](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/server-json/generic-server-json.md) · [MCP 授权规范](https://modelcontextprotocol.io/specification/latest/basic/authorization)
2. **把 GitHub 私有代理扩展成通用 MCP 代理。** Pocket Cloud 按用户保存凭据，Codex 只拿临时调用权限。用户授权一次，可以在多个频道选择不同的工具。默认启用经过确认的只读工具，写入、发送等操作单独确认。服务器自己声明的 `readOnlyHint` 只作为展示线索。 [MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)
3. **接入后用真实调用验收。** 把「能列出工具」和「工具已试跑」分开。用户选一个查询工具和测试输入，Voxi 实际调用并显示结果。只有本地安装包、`stdio` 或私网地址的服务，可以走家中电脑的主动连接器，由那台机器运行。 [MCP 传输规范](https://modelcontextprotocol.io/specification/latest/basic/transports)

### Skill 怎么改

现有导入器已经能从 skills.sh 和 GitHub 固定版本导入。下一步把它扩成通用 **Agent Skills** 导入器，按标准保留 `SKILL.md`、参考资料和模板，并在预览里列出脚本、环境依赖和需要的 MCP。用户可以先装 Skill，再补齐缺失的工具。含脚本的 Skill 放到独立沙箱或用户主机执行，沿用频道的授权范围。 [Agent Skills 规范](https://agentskills.io/specification)

我会把第一批实现范围定为 **远程 HTTPS MCP、公开访问和 API Key 授权、工具选择和真实试跑**。验收时选一个公开服务和一个带 Key 的服务，两者都通过同一套表单和代理接入，再各用 MiniCam 发一条任务。这样能验证我们扩展的是通用能力，之后再接 OAuth 和本地安装包。
