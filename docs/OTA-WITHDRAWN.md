# OTA 下线与聊天决策记录 — 2026-11-09

## 当前决定

用户原话：“这个模式不行。先把这个OTA功能下线吧，想清楚了再上。聊天记录里记得留好记录”。

本轮 OTA 方案撤回，停止上线。现有后台自动轮询 + 云端命令行发布缺少可见的固件列表、手动触发和完整升级状态，未满足用户期望。需要重新设计产品流程后再讨论上线，不把这次实验视为已验收功能。

## 已做过什么

- 基于 main 50a13a7 开发四款 S3 独立 OTA 构建、双槽布局、TLS/板型/大小/SHA 校验和启动确认/回退。
- 实现网关下载端点、原子发布脚本和首次 USB 分区迁移脚本；PR #2 处于实验分支，未合并 main。本会话未部署生产网关 OTA 接口、未发布生产 manifest，Pocket 后端未改。
- 用户明确授权烧录后，已确认正常音量加键对讲 MiniCam，16 MB Flash / 8 MB PSRAM。ROM 备份旧分区表/NVS/PHY 后迁移并烧录，配置保留，4G READY 恢复。
- 实机 Opus 上下行编解码和尾帧、10 秒 4G 下行播放通过；20 秒 PCM 压测关闭恢复时失败，开启恢复后一次补传、录音与发送 CRC 一致。真实语音人工验收、在线固件下载、切槽确认、断电和失败启动回退均未完成。
- 设备保存的 Wi-Fi 不可用，测试结束恢复 cellular。完整原始 Flash 备份未成功，只有 32768 字节分区/NVS/PHY 备份；私有备份留在工作目录，不提交。
- 已向用户说明当前没有固件列表页面或“立即升级”按钮；自动检查最早开机 60 秒、后续约 30 分钟且只支持 Wi-Fi。用户据此否定当前模式并要求下线。

## 本次下线操作

- 固件新增强制暂停开关，自动检查、下载、刷写和启动 OTA 路径不编入停用版；status 返回 otaEnabled=false、otaState=suspended。
- 采用当前双槽布局刷入停用应用，显式选择 app0；不改 bootloader/分区表/NVS，不重新格式化录音区。保留双槽只为避免再做破坏性的分区迁移，不表示 OTA 仍启用。
- 网关固件分发默认禁用，授权请求返回 410；服务器没有启用该开关的产品入口。发布和迁移 CLI 直接拒绝操作。
- 关闭 PR #2，保留分支、提交、测试和实机记录作为历史资料；旧候选固件包从交付输出目录撤回。
- 当前聊天不删除、不归档；本记录同步写入仓库交接入口，供之后续接工作时检索。

## 重新设计时要解决

固件版本/适用板型/兼容性可见、设备当前版本可见、可控升级触发、发布与回退的操作流程、进度和失败原因、Wi-Fi/4G 策略，以及通过实机正常/断网/断电/失败启动/语音回归测试。以上是待重新设计事项，不是自动恢复旧方案的任务。

相关历史：[实机记录](OTA-HARDWARE-2026-11-09.md)、[验证记录](OTA-VALIDATION.md)、[PR #2](https://github.com/castoryan-looper/Voxi/pull/2)。

## 下线验证结果

MiniCam 停用版应用及 app0 启动记录经 USB 写入并由 esptool 校验成功。重启后实测 otaEnabled=false、otaState=suspended、networkMode=cellular、cloudReady=true、audioCacheReady=true、displayReady=true，解码和扬声器错误均为 0。8 kbps Opus 实机解码及错误帧拒绝回归通过。网关完整测试 92 项、Python OTA/迁移保护测试 5 项通过；MiniCam 停用版编译通过。客户端不再执行自动升级。
