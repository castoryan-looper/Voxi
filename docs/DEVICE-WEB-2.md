# C6 Web-2 固件

参考 codex-pocket 02d6a7766fdf 的 Wi-Fi 策略和 BLE HID 旋钮实现。Voxi 是独立固件，更新 Pocket 仓库不会自动更新 Voxi。

- 最多记住 8 个 Wi-Fi；新网络保存后成为优先网络。断线后扫描并选择已保存网络，失败暂时退避；已连通时不主动换网。
- 已保存网络的密码留空即可复用。网页支持单独忘记网络，密码不回传网页。
- 蓝牙搜索后明确选择设备并配对；绑定成功后自动重连。旋转切换 4 个频道，PTT 使用设备 BOOT。蓝牙按压暂不映射 PTT。
- USB 和设备热点使用同一管理页面；本地 http://127.0.0.1:8788/ 刷新即可加载新版。
- 保存为 NVS blob，写入后逐字节回读比对，成功后显示配置编号并重启。重新连接 USB 后比对配置编号确认保留。
- 墨水屏合并重复状态、使用局部刷新，每 20 次变更做一次全刷。启动或定期全刷仍可能黑白闪烁；可通过网页运行时长和启动次数区分实际重启。
- TLS/WebSocket 在独立任务运行，音频及控制使用有界队列。错误时清空音频并重连，USB 配置循环继续运行。
- 页面诊断包含启动原因、运行时长、最小可用堆、连接阶段、最近错误。不同开机周期的启动次数不保证跨完全断电保留。

首次设置或此前保存未成功时，仍需填写 Wi-Fi、Voxi 设备令牌和 CA。Pocket 登录不等于设备已经有 Voxi 配置，也不会导入 Pocket 的服务器令牌。

验证：本地 C6 编译，管理页保存成功/失败/校验交互测试，网关与部署回归测试。真实旋钮配对、家庭网络自动切换和云端语音需在相应设备与有效配置下验证。

烧录修正：工厂分区固件不再写入 Arduino 默认的 boot_app0.bin（0xe000–0xffff），避免覆盖已有 NVS/PHY；保持原分区地址，避免迁移配置。

## 保存后的屏幕

配置有效时开机进入对讲主页，这是正常行为。主页显示 WiFi / Gateway 状态、USB 管理地址，BOOT+PWR 同按约 3 秒可再次显示设置页。管理网页也提供“设备屏幕显示设置入口 / 返回对讲”按钮。

- WIFI CONNECT：尚未连上无线网络。
- SYNC TIME：等待校时，以验证 TLS 证书。
- CLOUD CONNECT：尚未完成网关 WebSocket 连接。
- AI CONNECTING：网关已连接，正在等待原生语音会话握手。
- BACKEND ERROR：网关返回后端错误；具体原因看管理网页。
- READY：AI 会话已完成握手，可按 BOOT 对讲。

网关 healthz 的 ok 只表示服务进程存活，不代表 Pocket 原生语音已可用。网关会将 Pocket 的 HTTP 403/404/503 或 DNS/端口连接错误分别报告，避免统一显示 CONNECTING。

## 默认待机页与状态图标

开机默认显示频道待机页，未配置时显示 SETUP NEEDED，断网也保留此页。设置页通过 BOOT+PWR 按住 3 秒，或 USB 管理网页按钮进入。

顶部左侧 Wi-Fi 图标：连接时显示 1–3 级弧线，断开时显示斜线和 OFF。信号每 10 秒评估并带滞回，避免 RSSI 波动触发重复刷新。

顶部右侧电池图标：GPIO0 / ADC1 CH0，12-bit 校准毫伏采样，按官方板级例程的二倍分压换算；16 次平均，每 30 秒更新。使用官方 3.00–4.12V 区间估算百分比，前缀 ~ 表示估算，读数不在 2.8–4.5V 时显示 ?。该板没有在这里使用独立电量计或充电状态检测，因此不显示“正在充电”；USB 供电与电池充电会影响电压估算。

USB 自动切页：检测到电脑 USB 主机连接稳定 400ms 后显示 USB SETUP、管理地址 http://127.0.0.1:8788/ 和 Chrome/Edge 连接提示；断开后自动返回频道待机页。只改变显示页面，不重启设备，不清除配置，也不主动断开 AI 会话。充电器仅供电、未枚举 USB 主机时保持待机页。

## 长按对讲

BOOT 稳定按下达到 500ms 后进入录音；短按不发送 PTT、音频或创建云端回合。录音开始前丢弃麦克风积压，因此门限前的声音不会上传。继续按住讲话，松开结束并提交；为降低延迟，录音期间音频已流式上传，松开只需提交并请求生成。录音每轮最多 29 秒，超时停止后必须松开再按；PWR 组合键或云端未就绪不会触发录音。

待机页显示 RECORDING / THINKING / RECEIVING / READY。USB 设置页仍优先显示，后台对讲保持可用。云端缺少完整配置或语音后端未就绪时不录音。

服务器独立语音诊断（不需要设备在线）：

```bash
git -C ~/Voxi -c core.hooksPath=/dev/null pull --ff-only
docker exec -i voxi-gateway-1 node --input-type=module < ~/Voxi/gateway/diagnose-pocket.mjs
docker logs --since=3m codex-pocket-gateway-1 2>&1 | grep 'Native voice' | tail -n 10
```

诊断会占用唯一的原生语音会话，测试前可先断开设备的云端连接。诊断返回 READY 会主动关闭会话；最长 55 秒结束。它不会输出设备令牌或账号登录文件。

Pocket AVAS v3 后端适配：设备仍按住 0.5 秒开始录音，但按住期间的音频由云端暂存，松开才提交模型；服务端自动检测语句结束。等待回复和播放期间设备暂停接受下一轮 PTT，收到回复结束的 READY 后恢复。API Key 模式行为维持原实现。

云端配置记忆：管理页分开展示“云端配置已记住”和“AI 连接状态”，并分别显示令牌/证书是否存在；令牌不回显明文。保存时证书、令牌留空均保留已存值，改变 Wi-Fi 无需重新填写云端凭据。重启从 NVS 读回，配置有效时自动连接及重试；清除/擦除 NVS 或重新生成服务器凭据时才需要再次配置。

## 屏幕过程日志

USB 设置页和待机页都显示实时调试面板：HOLD 0.5s → RECORDING → SENDING → WAIT AI → PLAYING → READY。下方保留最近 3 条带开机秒数的事件，不包含密码、令牌或录音内容。

- MIC：麦克风实际读取的 PCM 字节数；REC 是按样本数换算的录音时长。
- PEAK：本轮麦克风最大幅度。一直为 0 时应检查音频采样；它不是准确的语音识别判断。
- TX：WebSocket 库接受发送的音频字节数，不代表 AI 已处理；Gateway recording ACK / Gateway submitted audio 才是网关返回的阶段确认。
- RX：设备收到的回复 PCM 字节数；有 RX 但无声音可继续排查播放路径。
- NOT READY / BOOT blocked：按键已检测到，但 AI 未就绪，因此没有录音。
- Clip too short：网关判定有效录音过短，没有提交模型。

墨水屏刷新有物理延迟，USB 页约每秒更新、主页面最多约每 500ms更新；短暂状态可能被合并，最近事件和计数仍保留。每 60 次有效画面变化做一次全刷，其他使用局部刷新。网页同步显示完整字节计数和最近事件。

按键名称：BOOT（GPIO9）是对讲键，按住超过 0.5 秒录音；PWR（GPIO2）是电源/设置组合键。当前软件未实现 PWR 单独关机，BOOT+PWR 同按 3 秒进入设置。发送缓冲使用 24 个 512B 小包（约 240ms 音频），录音入队有有界等待；发送失败分别报告 TX 队列满、WebSocket 发送失败、RX 队列满等，不再统一误报。最近故障在恢复 READY 后仍可从网页 lastFault 查看，重启后清除。

本地扬声器测试：管理网页提供“播放两声本地测试音”。测试绕过网络，使用同一 I2S/ES8311/功放链路；重新确认 DAC 未静音和功放使能，再播放约 750ms 的两声低幅度测试音。仅空闲时接受测试。SPK written 是 I2S 接受的样本数，peak 是实际输出数值峰值，errors 是 I2S 非超时错误次数；这些计数不能证明扬声器实际发声。

扬声器音量：DAC 固定 100（默认音量曲线为 0dB），改用单个 0–100 软件音量控制，默认 45。原先 DAC=80 对应约 -10dB，再叠加软件 45%，会重复衰减。网页可保存音量到 voxi-audio/volume，重启恢复；0 为静音。测试音和 AI 回复共用同一音量。

播放增益调整：小信号先提升 4 倍（约 12dB），大于 24000 的内部幅度经过连续软拐点压缩，最终幅度不超过 31000，再应用 0–100 用户音量，避免整数溢出和硬削波。它能提升较轻语音的响度，但不代表扬声器硬件功率提高。管理网页在设备状态读取成功后才显示音量区，断开连接时隐藏。

播放连续性：先预缓冲 120ms，开始后连续消耗余下样本，不再逐包等待低水位；网络断流时统计重新缓冲次数并等待恢复。I2S DMA 余量改为 60ms，USB CDC 发送缓冲增至 8KB，降低状态日志阻塞音频循环的可能。网页显示缓冲毫秒数和每轮重新缓冲次数。实际断续是否改善仍需设备连续对话验证。

## 上传队列修复（web-4）

上传改为每 40ms 合并一个 1920B PCM 包，松开时先补发最后不足一包的录音，再将 ptt_up 排到同一发送队列。录音期间采用半双工发送，避免同步 WebSocket 读取控制包时阻塞上传；释放并排空发送队列后恢复接收。录音期间暂时停用客户端心跳计时，回到接收时重新计时；断线后清空待发送数据并恢复重连，不能让未发队列阻止重连。

status 新增 networkLoopMaxMs、networkSendMaxMs（网络循环及单包发送最大耗时）。USB RPC upload_test 可在 READY/空闲时运行 3 秒静音上传自检；统计 micBytes 与 sentBytes 一致才通过。该测试不提交 ptt_up 给模型，结束会主动关闭测试连接、丢弃云端临时录音并重连；因此测试结束后的 OFFLINE 是预期动作，不代表自检失败。它只验证到网关的上传能力，不证明语音识别或回复质量。

音质连续性再优化：初始播放水位 200ms，每次缺包后增加 80ms，最多 360ms；每轮重新开始计算。语音首尾和缓冲断点加入 120 样本（5ms）淡入淡出，避免直接从非零样本切到静音导致点击声。该处理仅衰减边缘，不提高音量，已保存音量不变。改善情况仍需实际语音听测。

## 录音与网络解耦（web-5）

实际记录过网络读取阻塞 5.4 秒、单包发送 3.3 秒；短 RAM 队列不能保证持续采样。按住 BOOT 后将 PCM 暂存到内置 storage 分区的 /voxi-turn.pcm，松开才开启上传，按发送队列余量逐包读取文件；网络慢时暂停读文件，而不是继续往队列塞包。最后一包发出后才发送 ptt_up，并等待其发送完成再删除临时文件。连接失败则保留已写入的临时文件供排查；开始下一轮会覆盖这份临时录音，当前不自动重发，避免重复提交。

缓存支持挂载已有 SPIFFS/LittleFS；若均不能识别，仅当完整检查确认整个 storage 分区全为 0xff 才自动初始化。非空且无法识别时拒绝格式化。此次用户已授权在本机完整备份后初始化 storage；原始备份保存在 backups/（已排除 Git 上传），不更改 NVS 配置区。

upload_test 现使用 3 秒低幅度伪随机合成 PCM，随后模拟 3.5 秒发送停顿，再从 Flash 上传；字节数和 CRC32 必须都相同才通过。测试不提交给模型，最后主动重连。该自检验证缓存与上传完整性，不代替真实按键对话及听感测试。
