# 默认启用 Opus 上下行

用户约定：所有维护板型的普通对讲默认同时使用 Opus 录音上行和 Opus 回复下行。新板适配也遵循此约定，不再将上行编码限定为 S3。默认策略测试进入 CI。

- 上行：`opus-24000-uplink-v1`，24kHz 单声道，20ms 帧，16kbps，五帧合包。
- 下行：`opus-24000-v1`，24kHz 单声道，20ms 帧，16kbps。
- 网关必须确认两个格式，不支持时明确提示更新网关，不在普通对话中静默改用 PCM。
- `upload_test` 是明确的原始 PCM 大流量诊断，不代表普通对话使用 PCM；内部 Pocket 链路也仍使用 PCM。

## C6 内存管理

C6 没有 PSRAM。回复的 96KB PCM 播放缓存改为按阶段分配，而非永久占据静态 RAM；容量及播放门槛不变。开始普通 Opus 上传前，由 Arduino 主任务释放闲置播放缓存和解码器。编码通过临时 32KB 栈工作任务完成，网络任务同步等待每项操作，避免将 SILK 编码压入原来的 12KB 网络栈或 16KB主循环栈。

发送结尾帧后释放编码器和临时任务；网络故障、重连、待机也清理编码资源。收到回复 `audio_start` 时恢复播放缓存并初始化解码器。失败时明确报错并走现有重连，不静默退回 PCM。USB 编码自检使用同一路径。

状态字段 `uplinkOpusReady` 表示网关已协商上行，`opusUplinkDefault` 表示默认策略，`opusUplinkWorkerActive` 表示编码资源正在使用，`playbackMemoryAllocated` 表示当前分配了播放缓存。

## 验证边界

编译通过不等于 C6 内存和真实语音验收通过。需在真实 C6 上确认编码、网关解码与尾帧、编码结束释放资源、随后下行恢复及多轮对话；保留明确的未验证项。合成自检不能代替实际麦克风识别、弱网、长故事或耗电测试。

当前 C6 上行版本尚待 USB 设备物理唤醒后烧录和实测；上一次已烧录的 `53e3802` C6 固件只有 Opus 下行。不要将本页的实现说明当成已完成新固件实机验收。

实机循环检查：安装网关 Node 依赖及 pyserial 后，运行 `python tools/test_codec_cycle_device.py <已核对串口>`。三轮合成编码/解码检查不使用麦克风、不调用模型；真实语音另行验收。
