## 结论与边界

- 几十秒的停顿明显集中在蜂窝路径，尚不能仅凭日志归责于 SIM、运营商或模组中的某一项。
- Node WebSocket bufferedAmount 为 0 不能排除 Caddy、内核 TCP、运营商链路或模组里的积压和重传。
- BlockedChecks 是轮询检查次数，不是精确暂停时长，也不是卡顿次数。
- Wi-Fi 仍有两次缓冲耗尽。优先查 Pocket/WebRTC 媒体时间轴、平均供音速度、尾部结束时序；127.07s 整轮时间与 121.66s 源 PCM 之差包含起止开销，不能直接当成测得的纯网络延迟。
- 起播和恢复门槛不能制造上游未生成或链路未送达的音频。继续降低码率或增加超时不是已证实的根因修复。
- 源码中未发现需要修正的简单“每帧固定 sleep 20ms 累加”转发循环；不要把此前假设当作已证实缺陷。
