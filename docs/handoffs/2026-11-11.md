## 当前行为与验证

- 用户在「能力库」导入 Skill、搜索官方 MCP Registry 并试跑接入，再在「频道与助手」绑定能力。GitHub 专用接入限用户指定仓库的只读工具。通用接入首版支持公开或 API Key 的远程 Streamable HTTP，工具列出、试跑和执行审批分别有各自的状态。真实 Skill 导入与 Microsoft Learn 查询已验证，GitHub 用户授权、实际仓库试跑和 MiniCam 按键派发仍待实测。
- 「我的任务」按账户分页，展示问题、回答、状态和浏览器时区下精确到秒的时间。Token 使用执行端回传值，区分真实零用量与缺失统计。
- MiniCam 派发的任务保存待播状态。任务完成后，Pocket Cloud 在该设备回到原频道且空闲时读取保存的结果。Voxi 网关转发音频结束后回执。网关回执前断线时，结果可以在设备重连后补播。这个回执确认网关发完音频，实机扬声器播完仍需现场核对。
- 「读结果」或「刚刚那个任务好了没」优先查询当前设备在当前频道派发的任务。「新任务」显式另起任务。早先归档的行为描述已被最后一轮修复更新。语音仍走原有实时服务，逐字保真和 MiniCam 实际听感待验证。
- Voxi 网关 103 项、Pocket Cloud 269 项测试通过。桌面与手机宽度下验证了任务列表和翻页。自动播报、录音期间延后、断线补播、重复事件和只读追问通过回归测试。此前已通过 USB 确认 MiniCam 在 4G 下 READY，最后一轮自动播报部署后的物理 PTT 验收尚未进行。

## 下一次实机验收

1. 让 MiniCam 在 4G 下进入 Voxi Agent 频道，按 PTT 提交一条简短的只读任务。在网页「我的任务」记下任务短 ID。
2. 设备停在原频道，核对云端完成后能否自动播报，并将语音和网页保存的答案对照。
3. 说「刚刚那个任务好了没」和「读结果」，核对任务 ID 仍是同一条，网页任务数量没有增加。
4. 再测一次任务在设备离线期间完成的情况。重连并回到原频道后核对补播。能力库的实机验收可用绑定了代码审查 Skill 和 GitHub 只读 MCP 的频道完成。

主要入口是 Voxi 的 `gateway/user-capabilities.mjs`、`gateway/user-app.mjs` 和 `gateway/pocket.mjs`，以及 Pocket Cloud 的 `bridge/voxi_capabilities.py`、`bridge/voxi_remote_mcp.py`、`bridge/voxi_portal.py` 和 `bridge/voxi.py`。另一个固件工作树保留 11 月 4 日的 Opus 实验改动，独立于本日上线代码。
