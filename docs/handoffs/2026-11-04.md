## 当前实机

当前设备是正辰 MiniCam **2.0 英寸**版本，ESP32-S3 N16R8、16MB Flash / 8MB OPI PSRAM、ST7789、ES8388、ML307R。不是双眼屏，不是先前的微雪 AMOLED。

- 构建目标：`zhengchen_minicam_20`；最后烧录功能版本对应 `8b0704f`。
- 原电脑串口 COM15；换电脑后重新枚举，不能直接沿用。
- MAC `c4:9e:7e:09:53:d4`，协议设备 ID `esp32-d453097e9ec4`（保留历史倒序编码）。设备 ID 不随重命名改变，云端记忆绑定使用它。
- 当前已持久保存为 **4G 模式，Wi-Fi 关闭**；原有网关、令牌和 CA 留在设备 NVS。
- 主键短按开始录音，再短按发送；加减键短按调音量，长按约 0.7 秒切换频道。硬件电源键不适合持续按住录音。
- 录音上限仍为 20 秒；空闲 1 分钟待机。USB 在待机后可能需要拔插恢复数据通道。

详见[板型引脚和烧录记录](../zhengchen-minicam-2.0.md)、[4G 使用与验证](../MINICAM-4G.md)。

## 本次关键修复与验证

- 新板驱动、屏幕、音频、三键、PSRAM 和录音缓存已接入；用户确认屏幕及测试音正常。
- 录音锁存改为实际录音状态，避免 OPEN MIC 提示状态提前结束录音。
- ML307R 使用 UART1 GPIO47/48、921600 baud，UHCI DMA 接收；AT HEX 发送分片 730 字节。
- TLS 在 ESP32 执行，验证 CA 和主机名；错误 CA 拒连测试通过。4G 不允许关闭 TLS。
- WebSocket 心跳先处理接收数据，持续语音/控制帧刷新存活；长包解析区扩大，SIM 查询失败不直接判为掉卡，并保留具体断线原因。
- 回复协商 µ-law 24kHz，4G 预缓冲 6 秒、自适应最多 12 秒；短回复结束后可直接播放。
- 20 秒合成录音上传：960000 字节，采集和发送 CRC 相同，零溢出。
- 最后一轮真实语音：200160 字节上传；492000 字节回复完整播放；对应收发 CRC 相同，零重新缓冲、零 DMA 溢出、零扬声器错误。用户确认故事讲完且没掉线，连续在线超过 3 分钟。
- 四个固件目标均编译通过；网关 46 项测试通过；协议、心跳、按键与播放门控测试及 USB 页浏览器检查通过。

这是本机 SIM 的实测结果，不代表任意运营商、专网 APN、弱信号或无限长对话都已验证。4G 待机唤醒、侧键全部操作仍需继续实机验收。

## 换电脑接续

把两个仓库克隆到同一父目录：

```bash
git clone https://github.com/castoryan-looper/Voxi.git
git clone https://github.com/castoryan-looper/codex-pocket-cloud.git
```

已有仓库执行 `git pull --ff-only`。固件使用 Python 3.12/3.13 和 PlatformIO（参照 CI 中的版本），构建命令：

```bash
python -m pip install platformio==6.2.0
python -m platformio run -d firmware-c6 -e zhengchen_minicam_20
```

Windows 控制台可先设置 `PYTHONUTF8=1` 和 `PYTHONIOENCODING=utf-8`，避免 esptool 进度条编码错误。其他目标为 `waveshare_c6`、`waveshare_s3g`、`waveshare_amoled18_v2`。

在 Voxi 仓库启动 USB 配置页：

```bash
node tools/setup-server.mjs
```

浏览器打开 `http://127.0.0.1:8788/`。设备已有配置不必重复输入；更新前先实际检查串口占用。USB 管理页占用时需要断开后才能烧录。

**烧录前备份，不全片擦除，不覆盖 NVS；引导镜像保留 DIO，不能因为应用使用 qio_opi 就强制 QIO 引导。** 原厂分区和 VOXI 分区不同，首次迁移须按板型文档操作。

## 云端与凭据

网关 `43.160.215.253:9443`，TLS 开启。设备令牌保存在服务器 `/etc/voxi/gateway.env`，公共根 CA 为 `/etc/voxi/tls/ca.crt`。只在受控终端查看并直接填写设备配置页，不把结果提交到仓库。
