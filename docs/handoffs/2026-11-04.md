## 最新 Opus 低码率更新

录音上传优化见 [S3 上行 Opus](../MINICAM-UPLINK-OPUS.md)：MiniCam、AMOLED、S3G 使用 16kbps 上行、五帧合包和一次快速补传；网关解码后仍以 PCM 给 Pocket，不需更新 Pocket。真实 S3 编码测试通过，9600 字节原始测试音编码为 499 字节（含尾帧），网关解码验证通过；AMOLED 最近最慢帧约 9.558ms，尾帧能量通过。编码器需要上述 S3 两个任务各 32KB 栈，C6 不启用编码器。用户已部署 `595bf72`，云端自检和设备 `uplinkOpusReady:true` 均确认；最近真实对话结果见顶部摘要。新增首次 WebSocket 关闭原因记录用于继续排查 offline，不代表已修复所有中断。

后续已确认一次云端中断先出现 `Consent to send expired`，随后 `MediaStreamError`，即 ICE consent 检查过期；检查为何失败尚未确定。另一次上传失败中，网关连接 4/5/6 未收到 `ptt_up`，连接 7 完成 3.96 秒录音并正常回复，属于上传/补传链路故障，不能和 ICE 问题混为一谈。最新连续监控一轮有 3 次重新缓冲、最长设备接收空档 16.281 秒，但 4,046,400 字节完整播放、CRC 通过、解码及扬声器错误为 0、无新增模组断线。

分级待机已实现并烧录当前 MiniCam：1／5／15 分钟默认，可在 USB 管理页立即保存到 NVS。实测第一级关屏保 READY，第二级保 4G 数据但关闭语音会话，恢复约 12.12 秒且不重启；音频恢复测试输出 18000 采样、写入错误 0。启动优化去掉首次数据激活的固定等待。五个固件目标构建、网关 52 测试和原生待机测试通过；默认 15 分钟后物理唤醒及实际电流未在本轮重测。测试完毕恢复默认阈值，不要持续主动状态轮询而误以为待机失效。

已实现 `opus-24000-v1` 下行：24kHz 单声道、20ms、16kbps CBR，含帧序号约 2.2KB/s。按用户后续要求，统一覆盖当前维护的所有 C6/S3 板型和 Wi-Fi/4G，移除 PCM/µ-law 下行与自动回退，旧协议明确报错。标准音量＋录音目标已烧录统一格式及定期双向心跳固件，16kbps 编码帧到真实 S3 的自检通过（480 采样、约 3ms，非法和错序帧拒绝通过）。全部五个固件目标最终构建通过，网关 51 项测试通过。用户已部署统一版 `2711e7e`，自检和设备均确认 Opus-only 16kbps、READY。其他板型需分别烧录，不能认为未接入的设备已更新。后续又修复接收循环连续成功收帧时跳过心跳检查，MiniCam 两个目标构建通过、标准版已重新烧录；这个补丁无需再次部署网关。16kbps 真实长故事仍因 Pocket `MediaStreamError peer=closed outputting=True generation_done=False` 中断，网关关闭原因为 pocket_closed，非本轮 heartbeat_timeout；云端 WebRTC 会话提前关闭根因仍待排查。协议、依赖许可、部署与验证记录见 [MINICAM-OPUS.md](../MINICAM-OPUS.md)。

## 换电脑接续

把两个仓库克隆到同一父目录：

```bash
git clone https://github.com/castoryan-looper/Voxi.git
git clone https://github.com/castoryan-looper/codex-pocket-cloud.git
```

已有仓库执行 `git pull --ff-only`。固件使用 Python 3.12/3.13 和 PlatformIO（参照 CI 中的版本），构建命令：

```bash
python -m pip install platformio==6.2.0
python -m platformio run -d firmware-c6 -e zhengchen_minicam_20
```

Windows 控制台可先设置 `PYTHONUTF8=1` 和 `PYTHONIOENCODING=utf-8`，避免 esptool 进度条编码错误。其他目标为 `waveshare_c6`、`waveshare_s3g`、`waveshare_amoled18_v2`。

在 Voxi 仓库启动 USB 配置页：

```bash
node tools/setup-server.mjs
```

浏览器打开 `http://127.0.0.1:8788/`。设备已有配置不必重复输入；更新前先实际检查串口占用。USB 管理页占用时需要断开后才能烧录。

**烧录前备份，不全片擦除，不覆盖 NVS；引导镜像保留 DIO，不能因为应用使用 qio_opi 就强制 QIO 引导。** 原厂分区和 VOXI 分区不同，首次迁移须按板型文档操作。
