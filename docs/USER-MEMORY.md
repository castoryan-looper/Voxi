# 单设备绑定用户的长期记忆

第一版将一台设备固定绑定一个用户；不做声纹或说话人识别。固件在已鉴权WebSocket握手中携带稳定芯片编号，网关转发至Pocket。首次连接自动建立独立用户档案；后台可以改名、填写背景，或将设备绑定给已有用户。设备编号只是持有设备令牌的私有设备群内的归属标记，不是防伪身份证明；设备令牌仍需保密。

## 记忆如何积累

PTT松开后，用户PCM在内存中复制到有界后台队列，使用服务器已安装的Whisper模型转写；单工作队列、单CPU线程推理，不等待转写才开始AI回复。最多8条待转写，满队列或转写失败不打断对讲，并在后台显示错误。

每用户保留最近200条用户转写和最多100条记忆。不保存原始录音，也不保存/转写助手语音。自动提取只覆盖“我喜欢／不喜欢／偏好／习惯／希望你／希望以后／叫／的名字是”等明确表述，保留转写来源；它不是对任意对话的智能总结。转写和自动提取可能有误，可在后台纠正。后台个人背景用于手工添加更复杂的需求。

新连接或切换频道时，合成提示词注入该用户资料、最多30条记忆、最近8条用户陈述，总背景最多约10000字符。历史标注为可能有误的数据，当前用户的更正优先。不同用户的记忆互不加载。原生语音当前会话自身仍保有本轮对话上下文，后台异步转写不对正在讲话的会话热更新提示词。

## 后台管理

在公网管理员页面打开「用户与长期记忆」，点击读取并选择用户，可以修改称呼/背景、暂停记忆记录与加载、增改删除记忆、删除用户转写、清空背景/记忆/历史、变更设备绑定。

修改资料或记忆、删除记录及清空时，会断开该用户的当前设备连接，以清除已载入的旧上下文，设备自动重连；可能中断当前故事。页面对删除和清空进行确认。删除源转写同时删除仍关联到它的自动记忆；经管理员编辑的记忆已经独立，需另行删除。清空后已排队的旧转写不会重新写入。关闭记忆不删除已有数据，但停止新记录及加载；要彻底清除请使用清空。

设备绑定变更不会把旧用户数据迁给新用户。无设备编号的旧固件仍可正常对讲，但不记录或载入个人记忆，避免共享令牌导致串用户。后台读取历史仅限管理员会话。

## 部署与验收

先更新Pocket后端，再更新Voxi网关，最后将带设备编号的新固件烧录到需要启用记忆的板子。其他板子需各自更新，不能仅靠云端更新识别旧固件。

```bash
sudo python3 /usr/local/lib/codex-pocket-autodeploy/autodeploy.py run --retry
sudo python3 /usr/local/lib/codex-pocket-autodeploy/autodeploy.py status
# 等待部署完成后：
cd ~/Voxi
git -c core.hooksPath=/dev/null pull --ff-only
sudo bash deploy/deploy.sh
docker exec codex-pocket-gateway-1 python -c 'import os;from pathlib import Path;print("Whisper model ready:",(Path(os.environ["POCKET_MODEL_DIR"])/"model.bin").is_file())'
```

数据文件为Pocket持久状态目录的 `voxi-memory.sqlite3`，使用SQLite WAL；备份时使用SQLite备份方式或停止服务后复制数据库及WAL，不要只复制运行中的主文件。已有设备令牌、CA及管理员账户不变。

验收：在后台把设备自动建立的用户改名，设备说“我喜欢天文学”；等后台转写完成，确认出现正确记录/记忆。切换频道或重连后询问喜好，检查是否引用该记忆。再用另一台更新后的设备确认没有加载前者的内容；最后删除记忆并检查重连后不再加载。若看不到记录，检查后台待转写数量、错误及模型安装状态。

本地测试覆盖用户隔离、跨重启持久化、提示词实际注入、编辑/删除/暂停/清空、转写任务与删除的竞争、有界保留、设备编号转发及页面编辑。真实麦克风Whisper转写和云端跨会话听感需部署后验收，未用测试桩结果替代线上验证。
