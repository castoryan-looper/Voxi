# 设备登记、转移与移除（2026-11-11）

## 使用步骤

每台 ESP32 的唯一 ID 由固件读取芯片信息自动生成，格式为 `esp32-` 加 12 位十六进制字符。它不是用户 ID，也不是可以自由起的设备名称。换电脑、改名或重新烧录不会因此换 ID。

1. 用数据 USB 线连接实物，打开本机 USB 设置页，读取设备状态，复制“设备唯一 ID”。本地配置服务需要先启动。
2. 管理员进入“用户账户 → 管理用户 → 绑定设备”，核对接收用户已开通且启用网页登录账户，再粘贴真实 ID 登记。
3. 新令牌只显示一次。将它写入同一台实物的 USB 配置，保存并重启；设备进入 READY 才表示端到端接入成功。不要把令牌发送到聊天记录。

## 已有登记如何处理

- ID 已属于当前用户：重置令牌需输入完整 ID 确认，旧令牌随即失效。
- ID 属于其他用户：登记入口显示当前归属、原用户设备页链接，并选中转移入口。确认实物 ID 后执行“转移到当前用户并生成新令牌”。必须将新令牌写回实物，原用户的记忆、转写和任务留在原用户下。
- 以前随意填写的 ID：进入该登记所属用户的“绑定设备”，点行内“移除登记（停用）”，输入完整 ID 确认。无需删除用户。移除后旧令牌无法接入，也不会被旧版自动登记机制重新创建；以后可用真实 ID 重新登记。
- 设备名称可自由填写。管理员登记不构成设备持有证明；当前仍由管理员核对实物，普通用户没有自助跨账户转移权限。

## 部署与验证

先更新 Pocket Cloud，再更新 Voxi 网关并刷新页面。Pocket 的设备列表返回 `deviceLifecycleVersion: 1`；旧后端下转移和移除按钮禁用并提示升级。旧版保留令牌的公共 rebind 路径已拒绝，内网兼容接口未删除。

转移使用数据库事务核对预期原用户，防止过期页面覆盖新归属；只替换设备归属与令牌摘要。移除保留退役标记。两种操作都会关闭该设备的活动会话，其他设备不受影响。旧请求如已进入执行阶段不作为设备转移的一部分取消。

本轮本地验证：Voxi 网关 106 项测试通过；浏览器使用隔离示例数据验证了归属冲突、精确 ID 确认、转移后令牌展示、移除后列表。Pocket 全量 272 项中 271 项首轮通过；1 项既有音色转写测试因本地缺少 NumPy 报错，补齐测试虚拟环境依赖后该项复测通过。 配套 PR：[Voxi #23](https://github.com/castoryan-looper/Voxi/pull/23)、[Pocket #16](https://github.com/castoryan-looper/codex-pocket-cloud/pull/16)。尚未修改生产设备归属或令牌，尚未完成生产部署与实机 READY 验证。现有 HTTPS 证书未受本机浏览器信任，SSH 缺少已核验主机密钥，不能以本地通过替代上线验收。

本次只改变设备登记管理与 USB 页说明，不修改固件或分区，OTA 继续保持撤回。
